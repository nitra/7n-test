# Кап runtime-probe виходів (shape-summary, tmp-cwd) і bounded backoff на memory-guard відмови

## Контекст і постановка проблеми

Розтин великих LLM-запитів (124–177 тис. символів) з логу myllm-проксі
показав, що ~98% розміру давав **один рядок runtime-probe**:
`runtime-probe.mjs` серіалізував вихід probe-ованої функції через
`JSON.stringify` без ліміту, а `readSurvived("")` через відносний
`readFile(join("", 'COVERAGE.md'))` читав реальний файл проєкту з
успадкованої cwd — весь mutation-звіт потрапляв у промпт кожного
block-виклику gen-tests. Наслідки: серії запитів по ~30–40k токенів,
`400 prefill_memory_exceeded` від oMLX, недетерміновані «expected»
значення між машинами.

Другий бік: на memory-guard відмову `pi-client.mjs` реагував або
миттєвим повтором ідентичного промпту без затримки (старий баг гілки
`reset`), або миттєвим термінальним падінням (fix-fast, `6f63570`) —
хоча oMLX обслуговує один промпт одночасно, і відмова зазвичай
відображає залишкову пам'ять попереднього запиту, яка вивільняється
сама за десятки секунд (у логах той самий промпт пройшов через ~33 с).

Повна специфікація: `docs/specs/2026-07-04-omlx-prompt-budget.md`
(фаза 1). Серверна половина вектора: myllm
`docs/spec-llm-efficiency.md`, напрям F.

## Розглянуті варіанти

1. **Обрізання probe-виходу до N символів з маркером** — модель копіює
   обрізаний JSON у expected, тест гарантовано падає.
2. **Дроп завеликого probe-рядка** — втрачає інформацію про форму
   результату, яка і є цінністю probe.
3. **Shape-summary** (обрано) — замість значення стислий опис форми.
4. Для memory-guard: **fail-fast** (втрачає багатогодинні batch-прогони
   через тимчасовий стан), **shrink-and-retry** (не допомагає проти
   залишкової пам'яті чужого запиту), **bounded backoff** (обрано).

## Рішення

### 1. Кап probe-виходів у `npm/src/lib/runtime-probe.mjs`

- `PROBE_OUTPUT_MAX_CHARS = 600`: довший серіалізований вихід
  замінюється **shape-summary** — `[shape-summary, ~N chars] Array(34)
  of {file: string, mutants: Array(12)}` (рекурсивний `describeShape`,
  глибина 4, до 8 ключів на об'єкт; сам summary теж капається).
- `PROBE_MAX_ENTRIES_PER_EXPORT = 12`: ліміт probe-рядків на export.
- Застосовано до `probeModule` (виходи і constants) та `probeHelpers`.

### 2. Порожня tmp-cwd для probe-сабпроцесів (`spawnProbe`)

Усі probe-дочірні процеси запускаються з `cwd` у свіжій тимчасовій
директорії: відносні I/O-читання probe-ованих функцій не бачать файлів
проєкту — вихід детермінований і не може затягнути великий файл
репозиторію в промпт. Кап (1) лишається запобіжником для функцій, що
самі генерують великі структури.

### 3. Bounded backoff на memory-guard у `npm/src/lib/pi-client.mjs`

- Memory-guard відмова більше не термінальна одразу: до
  `N_PI_MEMORY_RETRY_ATTEMPTS` (default 3) спроб із затримками від
  `N_PI_MEMORY_RETRY_DELAY_MS` (default 15 000 мс) експоненційно
  (15s → 30s, стеля 60s) + jitter. Connection-помилки зберігають
  окремий швидший графік.
- Структуровані поля з тіла 400 (`omlx_code`, `estimated_bytes`,
  `limit_bytes`) парсяться в `error.omlxCode`/`estimatedBytes`/
  `limitBytes` — **тільки діагностика** (це байти GPU-пам'яті сервера,
  не міра для різання промпту); оригінальна помилка зберігається в
  `cause`.
- Тіло запиту друкується в stdout **лише на фінальному провалі**, не на
  проміжних спробах.

## Наслідки

- Block-промпти gen-tests обмежені: probe-секція одного export ≤
  ~7.2k символів замість необмеженої (спостерігалось 122k).
- Разові piky пам'яті oMLX більше не вбивають batch-прогін: до ~45 с
  очікування, потім чесний термінальний фейл із тілом запиту.
- Trade-off: legітимні probe-виходи > 600 символів деградують до
  shape-summary (менш точні expected у згенерованих тестах) — поріг
  переглядається емпірично; probes, що читали fixture відносно cwd
  проєкту, тепер повертають fallback (свідомо прийнято).
- Фаза 2 специфікації (спільний `prompt-budget.mjs`, батчинг
  fix-tests, per-call `maxTokens`) — окреме майбутнє рішення після
  переміру профілю розмірів.
