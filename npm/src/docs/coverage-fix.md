## Огляд

При виклику команди `n coverage --fix` система запускає pi-агента для автоматичного написання тестів, які покривають вцілілі мутанти Stryker. Замість одного величезного промпту на весь проєкт (що впиралося у 15-хвилинний timeout `callAgent` на великих scope) вцілілі мутанти діляться на batches за мутант-бюджетом — кожен batch отримує власний агентний виклик і власне часове вікно. Провал одного batch (напр. timeout) не зупиняє решту: логується з переліком файлів і прогін продовжується наступним batch.

## Поведінка

fixSurvivedMutants ділить вцілілі мутанти на batches (`batchSurvived`, дефолт 40 мутантів/batch, override `N_CURSOR_COVERAGE_FIX_BATCH_MUTANTS`) і послідовно запускає pi-агента на кожен. Файл ніколи не ріжеться навпіл між batches. Помилка одного batch ловиться і накопичується в `failed` (файли + текст помилки; можливий частковий прогрес на диску, бо агент пише файли напряму до кидання помилки), успішні batches — у `fixed`. Порожній список мутантів — no-op.
batchSurvived — жадібне пакування груп вцілілих мутантів по файлах у batches у межах мутант-бюджету, у порядку вхідного масиву.
buildFixPrompt формує детальний промпт для агента для набору груп (batch або весь `survived`), описуючи кожен вцілілий мутант разом із контекстом вихідного файлу.

## Публічний API

fixSurvivedMutants(survived, projectRoot, opts?) — запускає pi-агента батчами; повертає `{ fixed: string[], failed: { files, error }[] }`.
batchSurvived(survived, budget) — ділить групи вцілілих мутантів на batches за мутант-бюджетом.
buildFixPrompt(survived, projectRoot) — створює деталізований запит для агента з переліком вцілілих мутантів і контекстом з вихідного коду навколо кожної мутації.

## Гарантії поведінки

- Не змінює source-файли напряму — лише читає їх для контексту промпту; запис тестів виконує агент.
- Помилка одного batch не пропускається назовні і не зупиняє решту batches (fail-safe per-batch), а накопичується в `failed` для звіту.
