## Огляд

Файл відповідає за генерацію тестових файлів шляхом застосування стратегії багатоступеневого маршрутизації до кожного публічного експорту. Спочатку він визначає правила тестування та класифікує експорти за складністю, направляючи прості випадки на локальну модель $\text{pi}$ та складні — у хмару. Всі взаємодії з моделями ініціюються через $\text{pi SDK}$, а система використовує механізм захисту від збоїв, повертаючи порожнє значення замість винятків, особливо при відсутності конфігурації локальної моделі.

## Поведінка

findTestRules знаходить конфігурацію правил для тестів, обходячи каталог до 4 рівнів вгору.
startRe — регулярний вираз для виявлення викликів верхнього рівня, які виконуються як side-effect при завантаженні модуля.
fetchCalls — функція для перехоплення та виявлення всіх реальних викликів до функції `fetch` у модулі.
usedHelpers — функція для визначення та збору інформації про внутрішні допоміжні функції, які використовуються у публічних експортах.
buildGenTestsPrompt генерує зведений опис для генерації тестів, подаючи вміст кількох файлів для аналізу.
generateTests генерує тестові файли для наданого списку модулів, використовуючи багатоступеневий підхід: спочатку підхід з окремим описом для кожного експорту, задіявши локальну модель, а потім як запасний варіант — генерацію одного файлу.

## Публічний API

* findTestRules — Знаходить набір правил для тестів проєкту, піднімаючись на 4 рівня вище від поточної директорії.
* startRe — Ініціює процес повторного запуску.
* fetchCalls — Збирає список викликів.
* usedHelpers — Перелічує використані допоміжні функції.
* buildGenTestsPrompt — Формує для відображення стислий опис (використовується у тестах).
* generateTests — Створює тести для всіх наданих файлів. При наявності локальної LLM використовує маршрутизацію за рівнями експорту, інакше — генерує для кожного файлу окремо.

## Гарантії поведінки

* Перехоплює помилки і не пропускає винятків назовні (fail-safe).
* За певних помилок повертає порожнє значення (напр. `null`) замість винятку.
